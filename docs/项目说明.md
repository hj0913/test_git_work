# test_git_work 项目说明

> 本文档用于记录仓库的基本信息、使用方式与后续开发约定。

## 一、项目简介

`test_git_work` 是一个用于验证 Git 提交与推送流程的示例仓库。
它的目标不是实现复杂业务，而是提供一份**结构完整、可直接上手**的最小工程模板，
方便在此之上做实验、写示例或验证协作流程。

## 二、目录结构

建议的组织方式如下：

```
test_git_work/
├── docs/                  # 文档目录
│   └── 项目说明.md         # 本文件
├── src/                   # 源码目录
│   └── test_git_work/     # Python 包
├── tests/                 # 测试目录
├── README.md              # 仓库入口说明
└── pyproject.toml         # 项目与工具配置
```

采用 `src/` 布局的好处是：测试运行时不会误导入当前目录下的同名包，
可以更早发现「代码未正确安装」这类问题。

## 三、快速开始

### 1. 克隆仓库

```bash
git clone git@github.com:hj0913/test_git_work.git
cd test_git_work
```

### 2. 创建虚拟环境

```bash
python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
```

### 3. 安装依赖

```bash
pip install -e ".[dev]"
```

### 4. 运行

```bash
python -m test_git_work.main
```

## 五、Git 工作流

推荐的日常操作顺序：

```bash
git status                      # 1. 确认改动范围
git add <paths>                 # 2. 暂存需要的文件
git commit -m "docs: 补充项目说明"   # 3. 提交
git push origin HEAD            # 4. 推送
```

分支命名建议：

- 功能开发：`feat/<简短描述>`
- 缺陷修复：`fix/<简短描述>`
- 文档维护：`docs/<简短描述>`

## 六、常见问题

**Q: `git push` 提示 `Everything up-to-date`？**

说明本地与远程已一致，没有新的提交需要推送。先用 `git log --oneline -5`
确认提交是否真的创建成功。

**Q: 提交后发现漏了文件？**

```bash
git add <漏掉的文件>
git commit --amend --no-edit
```

注意：仅在该提交尚未推送到远程、或分支为个人分支时使用。

**Q: 想撤销最近的提交但保留改动？**

```bash
git reset --soft HEAD~1
```

改动会回到暂存区，可以重新组织提交内容。

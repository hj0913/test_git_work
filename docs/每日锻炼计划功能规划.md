## 1. 背景与目标

### 1.1 背景

WHO 建议成年人每周至少 **150 分钟中等强度有氧** + **2 次力量训练**，但现实中达标率极低。阻碍不在意愿，而在三个具体缺口：

| 缺口 | 用户的实际困境 |
|------|---------------|
| 不会排 | 知道要练，但不知道「一周练几天、每天练什么、练多少」 |
| 不会加 | 长期用同一个重量、同一组数，第 6 周开始毫无变化，进而放弃 |
| 不会停 | 状态好就猛加量，膝盖/腰出问题后彻底停练 |

而现有健身 App 的普遍做法是「给一个固定模板 + 打卡日历」：模板僵化（不看你的时间和器械条件）、没有渐进逻辑（下周和本周完全一样）、没有负荷监控（加量越过安全区也不提醒）。

本方案的核心思路是：**把训练计划当成一个可计算的排程问题**——输入是训练者画像（目标、水平、每周天数、单次时长、器械条件），输出是「一周分化模板 + 每次课的组次处方 + 逐周推进曲线」，并把「进度推进」和「安全边界」都做成系统职责而非用户自律。

### 1.2 目标

| 目标类型 | 描述 | 衡量方式 |
|---------|------|---------|
| 产品目标 | 用户只需回答 5 个问题，就能拿到一份可直接执行的周训练计划 | 首次配置完成率 |
| 用户目标 | 每次进健身房不需要决策：练什么、多重、几组、休息多久都已给出 | 单次训练执行完成率 |
| 用户目标 | 训练负荷持续进步且不受伤 | 12 周负荷提升率、伤停率 |
| 技术目标 | 处方可复现、可解释、可离线计算 | 纯函数可单测、算法与 UI 解耦 |

### 1.3 非目标（本期不做）

- 不做医学诊断、康复处方与疾病人群训练建议（仅做「伤停部位静默 + 就医提示」）；
- 不做动作识别与姿态纠正（摄像头 / 可穿戴传感器）；
- 不做饮食、热量与体重管理（本期只负责「练」）；
- 不做社交 PK、排行榜、组队打卡；
- 不采集医疗隐私数据；伤停记录仅本地保存，不做云端分析。

## 4. 训练计划生成算法

算法实现见 `src/exercise_plan.py`，本节所有表格均为该脚本在 `Profile(age=30, level="中级", days_per_week=4, session_minutes=70)` 下的实跑结果。

### 4.1 输入参数

| 参数 | 含义 | 默认值 | 取值范围 |
|------|------|--------|---------|
| `goal` | 训练目标 | 增肌 | 增肌 / 减脂 / 综合 |
| `level` | 经验水平 | 中级 | 新手 / 中级 / 进阶 |
| `days_per_week` | 每周训练天数 | 4 | 2–5 |
| `session_minutes` | 单次可训练时长 | 70 | 40–90 |
| `equipment` | 器械条件 | 健身房 | 健身房 / 哑铃 / 徒手 |
| `age` | 年龄（算心率区间） | — | 14–75 |
| `injuries` | 伤停部位 | 空 | 部位多选 |

### 4.2 分化方式选择

训练天数决定分化结构；同一肌群的两次训练间隔必须 ≥ 48 h，因此**不允许出现「周一胸、周二再胸」**这类排法。

| 每周天数 | 分化方式 | 排程示例 |
|---------|---------|---------|
| 2 | 全身 x2 | 周一全身 A / 周四全身 B |
| 3 | 全身 x3 | 周一 / 周三 / 周五，A-B-A 轮换 |
| 4 | 上下肢 x2 | 周一上肢推 / 周二下肢 A / 周四上肢拉 / 周六下肢 B |
| 5 | 推拉腿 + 上下 | 周一推 / 周二拉 / 周四腿 / 周五上肢 / 周日下肢 |

### 4.3 剂量推进：双进阶（Double Progression）

单个动作的推进不做「每周加 2.5 kg」这种线性假设，而是经典的双进阶：

```
中周期（4 周）
├─ W1  负荷 = 块基准，次数 = 区间下限
├─ W2  负荷不变，次数 = 下限 + 1
├─ W3  负荷不变，次数 = 区间上限   ← 达成即视为「已具备加片条件」
└─ W4  减载：负荷 x 0.70，组数 x 0.60，次数回到下限
下一个中周期基准负荷 = 上周期的块基准 x (1 + 递增率)
```

递增率按经验水平区分（越进阶越慢）：

| 水平 | 每中周期递增 | 每周每大肌群组数目标 |
|------|------------|-------------------|
| 新手 | +5% | 4–12 |
| 中级 | +2.5% | 6–18 |
| 进阶 | +1.25% | 8–24 |

```python
def prescribe(exercise: Exercise, week_index: int, level: str = "中级") -> Prescription:
    """双进阶处方：块内先加次数、块末加配重、第 4 周减载。"""
    block, week_in_block = divmod(week_index, BLOCK_WEEKS)
    block_base = round_to_plate(exercise.base_load * (1 + LEVEL_BLOCK_INCREMENT[level]) ** block)

    if week_in_block == BLOCK_WEEKS - 1:                       # 减载周
        return Prescription(round_to_plate(block_base * DELOAD_LOAD_FACTOR),
                            exercise.reps_low, DELOAD_SET_FACTOR)

    reps = min(exercise.reps_low + week_in_block, exercise.reps_high)
    return Prescription(block_base, reps, 1.0)
```

要点说明：

- `round_to_plate` 把负荷向下/就近取整到 **2.5 kg**（最小配重片），避免出现「61.8 kg」这种无法上杠的数字；正因如此，进阶期会出现「某个中周期内深蹲从 80 → 82.5 → 85」这种以配重片为台阶的增长。
- 减载周**不改变次数**，只降负荷与组数，目的是维持动作模式与技术，同时把疲劳清空。
- 块末加片幅度按水平区分：新手每 4 周 +5%（约 1 片），进阶每 4 周 +1.25%——同样是「走到次数上限就加片」的规则，对进阶者更慢，因为其绝对负荷更大。

**实跑：12 周（3 个中周期）负荷曲线，中级水平**

| 周 | 阶段 | 深蹲 | 卧推 | 硬拉 | 次数目标 | 组数系数 |
|----|------|-----|------|------|---------|---------|
| W1 | 递增 W1 | 80.0 | 60.0 | 100.0 | 5/6 | 1.0 |
| W2 | 递增 W2 | 80.0 | 60.0 | 100.0 | 6/7 | 1.0 |
| W3 | 递增 W3 | 80.0 | 60.0 | 100.0 | 6/8 | 1.0 |
| W4 | **减载** | 55.0 | 42.5 | 70.0 | 5/6 | 0.6 |
| W5 | 递增 W1 | 82.5 | 62.5 | 102.5 | 5/6 | 1.0 |
| W6 | 递增 W2 | 82.5 | 62.5 | 102.5 | 6/7 | 1.0 |
| W7 | 递增 W3 | 82.5 | 62.5 | 102.5 | 6/8 | 1.0 |
| W8 | **减载** | 57.5 | 45.0 | 72.5 | 5/6 | 0.6 |

### 4.4 容量与时长双重约束

处方不仅要「量够」，还要「装得进一次训练」。两个约束必须同时满足：

**约束一：周容量落在水平区间内。** 按大肌群归并统计（三头/二头合并为手臂，臀/腘绳/后链合并为后链），避免小肌群划分过细导致误报。

**约束二：单次时长不超过用户填写的可训练时长。**

```python
def session_minutes(session: Session) -> int:
    """估算单次训练时长（分钟）= 热身 + Σ组(净耗时 + 组间歇) + 拉伸。"""
    work_sec = sum(e.sets * (e.set_sec + e.rest_sec) for e in session.exercises)
    return round(session.warmup_min + work_sec / 60 + session.cooldown_min)
```

其中单组净耗时按 45 s 计（含离心控制与调整），组间歇按动作类型取 60–180 s。**实跑（中级，目标单次 70 min）**

| 训练日 | 组数 | 时长（估） | 是否超时 |
|--------|------|-----------|---------|
| 上肢推（胸 / 肩 / 三头） | 20 | 62 min | 否 |
| 下肢 A（股四头主导） | 20 | 64 min | 否 |
| 上肢拉（背 / 后肩 / 二头） | 20 | 60 min | 否 |
| 下肢 B（髋主导 / 后链） | 17 | 56 min | 否 |

|--------|--------|---------|--------|------|

> 时长冲突的处理优先级（对应异常 E3）：① 先削减小肌群孤立动作的最末组 → ② 减少辅助动作的组数 → ③ 缩短组间歇（仅限孤立动作，复合动作保持 ≥ 120 s）→ ④ 提示用户「本日容量低于水平下限」但不擅自加时长。**任何时候不通过压缩复合动作的组间歇来「塞进」容量。**

### 4.5 强度分区与有氧处方

心率区间使用 Tanaka 公式（`HRmax = 208 − 0.7 × age`），比 `220 − age` 在 40 岁以上人群中偏差更小。

**实跑（年龄 30，HRmax = 187 bpm）**

| 区间 | 心率（bpm） | 用途 |
|------|------------|------|
| Zone 1 恢复 | 94 – 112 | 训练日热身、组间主动恢复 |
| Zone 2 有氧基础 | 112 – 131 | **恢复日有氧主区间**，周累计 150 min |
| Zone 3 节奏 | 131 – 150 | 减脂人群可部分替代 Zone 2 |
| Zone 4 阈值 | 150 – 168 | 进阶者可加 1 次/周，每次 ≤ 20 min |
| Zone 5 最大摄氧 | 168 – 187 | 本期不主动处方，仅展示 |

力量训练强度以 RPE 标注：复合动作主项 **RPE 7–8**（留 2–3 次余力），孤立动作为 **RPE 8–9**；减载周全部降到 **RPE 5–6**。

### 4.6 负荷监控（ACWR）

急性:慢性负荷比 = 最近 7 天负荷 / 最近 28 天平均周负荷，单次课负荷用 sRPE（`RPE × 时长(min)`）表示。**实跑（单次课 sRPE = 7 × 70 = 490，常规周负荷 = 1960）**

| 场景 | ACWR | 判定 |
|------|------|------|
| 按计划推进 | 1.00 | 安全区 ✔ |
| 突然加量 40% | 1.40 | 超载风险 ⚠（冻结加量，本周不再加片） |
| 减载周（-40%） | 0.60 | 负荷回落（减载期正常，不告警） |

> 判定语义要点：ACWR **低于 0.8 不等于告警**。减载周本来就要掉到 0.6 附近，若一律按「不安全」提示，用户会主动跳过减载周——反而不安全。因此只有 `ACWR > 1.3` 触发告警，`< 0.8` 仅在**非减载周**出现时才提示「近期负荷不足」。

## 6. 技术方案

### 6.1 分层架构

```
┌───────────────────────────────────────────────┐
│ 表现层   计划配置 / 今日训练页 / 休息计时 / 趋势 │
├───────────────────────────────────────────────┤
│ 业务层   分化生成 / 双进阶处方 / 容量校验 / ACWR │
├───────────────────────────────────────────────┤
│ 调度层   训练日提醒（复用周计划引擎）/ 休息计时器 │
├───────────────────────────────────────────────┤
│ 数据层   本地存储（默认）/ 云同步（可选）        │
├───────────────────────────────────────────────┤
│ 平台层   通知 API / 前台服务计时器 / 健康数据写入 │
└───────────────────────────────────────────────┘
```

业务层全部为**纯函数**：给定（画像, 周序号）必然得到同一处方，便于单测与离线计算；UI 只做展示与采集。

### 6.2 数据模型

```python
from dataclasses import dataclass, field
from datetime import date, datetime

@dataclass
class Exercise:
    name: str
    muscle: str          # 目标肌群
    sets: int
    reps_low: int
    reps_high: int
    rest_sec: int
    base_load: float     # 基准负荷 kg（自重记 0）
    progress: str = "double"     # 进阶方式：double / reps_only / hold

@dataclass
class Session:
    weekday: int                 # 0=周一 … 6=周日
    name: str
    warmup_min: int
    cooldown_min: int
    exercises: list[Exercise] = field(default_factory=list)

@dataclass
class SetLog:
    exercise: str
    set_index: int
    load: float
    reps: int
    rpe: int | None = None
    done_at: datetime | None = None

@dataclass
class SessionLog:
    day: date
    session_name: str
    sets: list[SetLog] = field(default_factory=list)
    duration_min: int = 0

@dataclass
class PlanProfile:
    age: int
    goal: str = "增肌"
    level: str = "中级"
    days_per_week: int = 4
    session_minutes: int = 70
    equipment: str = "健身房"
    injuries: list[str] = field(default_factory=list)
```

### 6.3 核心接口

| 接口 | 签名 | 说明 |
|------|------|------|
| 生成分化 | `build_split(profile) -> list[Session]` | 按天数选分化，纯函数 |
| 生成处方 | `prescribe(exercise, week_index, level) -> Prescription` | 双进阶，纯函数 |
| 估算时长 | `session_minutes(session) -> int` | 容量-时长双约束 |
| 周容量 | `weekly_volume(sessions, set_factor) -> dict[str, int]` | 大肌群归并统计 |
| 容量校验 | `validate_volume(profile, volume) -> list[Warning]` | 返回偏离项与建议 |
| 心率区间 | `heart_rate_zones(age) -> dict[str, tuple[int, int]]` | Tanaka 公式 |
| 负荷监控 | `acwr(acute, chronic) -> float` | 越界触发冻结加量提示 |
| 打卡 | `log_set(day, exercise, set_index, load, reps) -> SetLog` | 幂等：同组重复提交只记一次 |
| 顺延 | `reschedule(from_day, to_day) -> list[Session]` | 保证同肌群间隔 ≥ 48 h |
| 周切换 | `on_week_change(week_index) -> None` | 周一 00:00 触发，进入下一个中周期判定 |

### 6.4 关键技术点

| 关键点 | 方案 |
|--------|------|
| **打卡幂等** | 以 `(day, session_name, exercise, set_index)` 为唯一键，重复提交覆盖而非累加 |
| **休息计时** | 前台用 `Timer`，退到后台用系统级倒计时通知；不允许依赖常驻进程（否则息屏后计时失准） |
| **周切换** | 按本地日历日判断「本周属于第几个中周期」，不使用「距首次训练的天数」累加，避免漏练几天后周期错位 |
| **加片判定** | 只有 W3 的打卡数据满足「全部组达到次数上限」才推进下一块基准负荷；否则沿用（E4） |
| **伤停静默** | 伤停部位的动作从当周处方中移除，由同模式动作补位；无补位动作时该部位本周组数记为 0 并提示容量不足 |
| **无器械降级** | 动作替换表按「同肌群 + 同运动模式」定义，负荷改由自重 + 难度系数表示，容量折减 20% |
| **省电** | 恢复日有氧不做 GPS 追踪，仅记时长与心率区间；不做后台常驻定位 |

## 7. 边界与异常

| 编号 | 场景 | 处理 |
|------|------|------|
| E1 | 每周仅 2 天可训练 | 退化为全身 x2，每肌群周组数取区间下限，优先保留复合动作 |
| E2 | 单次可训练 40 min 以下 | 削减辅助动作，每肌群仅保留 1 个复合动作；提示「当前时长无法覆盖全部肌群」 |
| E3 | 容量装不进时长 | 按 4.4 的优先级削减：孤立动作末组 → 辅助组数 → 孤立组间歇 → 提示容量不足 |
| E4 | W3 次数未达上限 | 不加片，下一中周期沿用同一块基准负荷 |
| E5 | 连续两周缺席训练 | 下一周重复当前中周期的 W1（不跳周），容量取区间下限；连续 3 周缺席则回到「重新配置」引导 |
| E6 | 漏练单次训练日 | 顺延到下一个非训练日，**不把两个训练日合并到同一天**；若顺延后同肌群间隔 < 48 h，则该次改为 Zone 2 有氧 |
| E7 | 减载周用户强行加量 | 允许记录实际负荷，但在 `sRPE` 与 ACWR 计算中保留真实值；若 ACWR > 1.3 触发告警 |
| E8 | 用户修改经验水平 | 只影响下一个中周期的递增率，当前中周期不改（避免当周处方突变） |
| E9 | 伤停部位是复合动作主项（如腰伤 -> 硬拉） | 该动作整体移除，替换为同肌群非脊柱负荷动作；无替代时置 0 并提示 |
| E10 | 用户手动修改处方（如改组数） | 允许，但标记该动作为「手动覆盖」，后续中周期推进不再自动改动它 |
| E11 | 打卡时间跨零点（夜练） | 以会话开始时间归属日期，不按 `done_at` 切日，避免一次训练被拆成两天 |
| E12 | 时区变更 / 旅行 | 训练日提醒按本地时区重算；中周期周序号保持不变（不因旅行跳周） |
| E13 | 用户年龄 < 18 或 > 65 | 不阻断，但默认降为新手模板并把有氧上限收紧至 Zone 3，同时提示就医/教练咨询 |

## 8. 指标与埋点

### 8.1 北极星指标

**每周达成「计划训练次数」的用户占比**（分母为当周配置了计划的用户）。选择「达成次数」而非「总训练时长」，是因为本方案的核心价值是「按计划执行」而非「练得久」。

### 8.2 关键指标

| 指标 | 定义 |
|------|------|
| 首次配置完成率 | 进入配置流程并生成计划的用户占比 |
| 单次训练完成率 | 打卡组数 / 处方组数（≥ 80% 记为完成） |
| 12 周负荷提升率 | 主项块基准负荷的 12 周涨幅 |
| 减载周执行率 | 减载周实际容量 / 常规周容量（目标 0.6–0.7） |
| 容量偏离率 | 周容量落在推荐区间外的周次占比 |
| 动作替换率 | 触发替换的动作数 / 处方动作数 |
| ACWR 越界率 | 7 日 ACWR > 1.3 的周次占比（安全指标，越低越好） |
| 顺延率 | 触发顺延的训练日占比 |

### 8.3 埋点事件

| 事件名 | 触发时机 | 关键参数 |
|--------|---------|---------|
| `plan_configured` | 首次生成计划 | goal, level, days_per_week, session_minutes, equipment |
| `split_generated` | 生成一周分化 | split_type, training_days, total_sets |
| `session_started` | 开始单次训练 | weekday, session_name, week_index, phase |
| `set_logged` | 完成一组 | exercise, set_index, load, reps, rpe |
| `session_finished` | 结束训练 | duration_min, sets_done, sets_planned |
| `volume_warned` | 容量偏离提示 | muscle_group, sets, target_low, target_high |
| `load_progressed` | 进入新中周期 | exercise, old_base, new_base, increment |
| `deload_started` | 进入减载周 | week_index, set_factor, load_factor |
| `exercise_swapped` | 动作替换 | from_exercise, to_exercise, reason(equipment/injury) |
| `acwr_alerted` | ACWR 越界告警 | acwr, acute_load, chronic_load |
| `session_rescheduled` | 顺延训练日 | from_day, to_day, reason |

## 9. 测试计划

### 9.1 单元测试

- `prescribe`：验证块内次数递增（下限→上限）、减载周系数（0.70 / 0.60）、块间递增率（新手 5% / 中级 2.5% / 进阶 1.25%）、2.5 kg 取整不产生负增长；
- `build_split`：2/3/4/5 天各自的分化结构与同肌群间隔 ≥ 48 h；
- `weekly_volume`：大肌群归并与减载系数统计正确；
- `session_minutes`：边界（40 / 70 / 90 min）下的超时判定；
- `heart_rate_zones`：不同年龄下区间单调、不重叠；
- `acwr`：0.8 / 1.3 边界、减载周 0.6 不告警、慢性负荷为 0 抛错。

### 9.2 集成测试

- 配置 → 生成分化 → 生成处方 → 打卡 → 下一周推进 全链路；
- W3 未达次数上限 → 下一中周期沿用旧基准（E4）；
- 伤停静默 → 动作替换 → 容量重算 → 提示；
- 漏练顺延 → 同肌群间隔校验 → 转 Zone 2 有氧（E6）；
- 跨零点打卡归属当日（E11）。

### 9.3 验收清单

- [ ] 5 项配置即可生成可直接执行的一周计划
- [ ] 每个训练日时长估算不超过用户填写值（±5 min 容差）
- [ ] 常规周各肌群组数落在该水平区间内，或明确提示偏离
- [ ] 12 周负荷曲线单调递增（块内次数递增、块间配重递增），减载周按 -30% / -40% 生效
- [ ] 同一肌群两次训练间隔 ≥ 48 h
- [ ] 同组重复点击打卡不重复计数
- [ ] 后台 / 息屏下休息计时误差 ≤ 1 s
- [ ] 减载周不触发 ACWR 告警，非减载周 ACWR > 1.3 触发告警

## 11. 风险

| 风险 | 影响 | 应对 |
|------|------|------|
| 打卡数据不完整 | 加片判定失真、趋势图无意义 | 支持「练后补录」，加片判定按已打卡组数比例折算（≥ 80% 视为达成） |
| 用户跳过减载周 | 疲劳累积、伤病风险上升 | 减载周在日历上明确标注并提前一周预告，ACWR 不告警以免误判为「负荷不足」 |
| 器械条件与模板不匹配 | 计划无法执行，直接放弃 | 首次配置即绑定器械条件，生成时替换而非事后报错 |
| 容量区间偏专业，用户不理解 | 提示被忽略 | 提示语用「本周胸部训练偏少，建议加 1 个动作」而非「组数低于 10」 |
| 组间歇计时在后台失准 | 训练节奏被打乱 | 使用系统级倒计时通知，不依赖进程存活 |
| 中周期推进过快导致受伤 | 安全指标恶化 | 加片幅度按水平分档 + ACWR 守门 + 减载周强制 |
| 训练提醒与喝水提醒冲突 | 通知轰炸 | 复用同一周计划引擎统一排程，训练提醒优先，喝水提醒在其前后各留 15 min 静默 |

## 12. 待确认事项

1. **目标默认值**：默认「增肌 + 中级 + 4 天 + 70 min」是否符合主流用户画像？
2. **器械条件的粒度**：三档（健身房 / 哑铃 / 徒手）是否够用，是否需要「仅弹力带」「仅单杠」等细化？
3. **有氧处方归属**：Zone 2 有氧放在本模块还是写在喝水/运动模块？是否与后续「跑步计划」模块重复？
4. **是否需要接入健康平台**：写入 Apple Health / Google Fit 的锻炼记录？（涉及权限与合规）
5. **容量区间的数据来源**：当前区间为训练学惯例值，是否需要引入文献引用并在文档中标注出处？
6. **手动覆盖的边界**：用户手动改过的动作是否永久停用自动推进（当前设计是永久，是否需要「恢复自动」入口）？
7. **休息计时默认值**：复合动作 180 s 对新手是否过长，是否按水平再分档？

## 附录：名词表

| 名词 | 含义 |
|------|------|
| 分化（Split） | 一周内各训练日练哪些肌群的划分方式，如上下肢分化、推拉腿分化 |
| 中周期（Mesocycle） | 本方案中为 4 周：3 周递增 + 1 周减载 |
| 双进阶（Double Progression） | 先在次数区间内递增，达到上限后再增加配重，重新回到次数下限 |
| 减载（Deload） | 主动降低负荷（-30%）与组数（-40%）的一周，用于清除疲劳 |
| 组间歇（Rest） | 两组之间的休息时长，复合动作 120–180 s，孤立动作 60–90 s |
| RPE | 自感用力程度（1–10），RPE 8 表示「还能再做 2 次」 |
| sRPE | 单次课负荷 = RPE × 时长（分钟） |
| ACWR | 急慢性负荷比 = 最近 7 天负荷 / 最近 28 天平均周负荷，安全区 0.8–1.3 |
| Tanaka 公式 | 最大心率估算：`HRmax = 208 − 0.7 × age` |
| Zone 2 | 60–70% HRmax 的有氧强度区间，用于打有氧基础 |
| 最小配重片 | 健身房最小可加减重量，本方案取 2.5 kg，所有负荷取整到该倍数 |
